# Spike 0.5: dockutil `--list` Output Format & Plist Read Strategy

**Status:** Completed  
**Date:** 2026-10-19  
**Target:** `oh-my-dock` Dock State Reading Strategy (`App/Resources/Helpers/dockutil 3.1.3`)  
**Author:** Research Sub-agent  

---

## 1. Executive Summary & Recommendation

### Recommendation
**Read the Dock state directly from the Dock preferences plist in Swift using `CFPreferences` / `PropertyListSerialization` for all read operations. Keep the bundled `dockutil` CLI binary solely for mutating operations (`--add`, `--remove`, `--move`).**

### Key Findings
1. **Critical Data Loss in `--list`**:
   - **Spacers**: Standard spacers (`spacer-tile`), small spacers (`small-spacer-tile`), and flex spacers (`flex-spacer-tile`) produce **byte-for-byte identical output** (`\t\tpersistentApps\t<plist>\t`). It is completely impossible to reconstruct `SpacerKind` (`.normal`, `.small`, `.flex`) from `--list`.
   - **Folders / Stacks**: `--list` discards all view (`showas`: fan, grid, list), display (`displayas`: stack, folder), and sorting (`arrangement`: name, date added, etc.) options.
   - **Identity**: `GUID`s are discarded, making it impossible to uniquely track tiles with duplicate labels or identify specific instances.
   - **Tile Types**: `tile-type` is omitted entirely; distinguishing a directory from a file in `persistentOthers` requires synchronous filesystem checks that fail on unmounted drives, network volumes, or deleted items.
2. **Fragile Delimiter**: Fields are separated by raw ASCII tabs (`\t`) without quoting or escaping. A label containing a tab character shifts all subsequent columns into wrong fields.
3. **Performance**: Spawning `dockutil --list` incurs process launch and IPC overhead (~50–100ms) compared to direct in-process reading of `com.apple.dock` via `CFPreferencesCopyAppValue` or `PropertyListSerialization` (< 1ms).

### Format Specification from `dockutil 3.1.3` Source (`Dock.swift:150-155`)
```swift
func printList() {
    forEach() { tile in
        print("\(printOptional(tile.label))\t\(printOptional(tile.url))\t\(tile.section)\t\(path)\t\(printOptional(tile.bundleIdentifier))")
    }
}
```
Every output line consists of **5 tab-separated fields**:
1. `tile.label` (`tile-data.file-label` or `tile-data.label`, or empty string `""` if nil)
2. `tile.url` (`tile-data.file-data._CFURLString` or `tile-data.url._CFURLString`, or `""` if nil)
3. `tile.section` (Swift enum case: `persistentApps`, `recentApps`, or `persistentOthers`)
4. `path` (the plist path argument passed to dockutil)
5. `tile.bundleIdentifier` (`tile-data.bundle-identifier`, or `""` if nil)

## 4. Ambiguity & Edge-Case Findings

### 1. Spacers Cannot Be Distinguished
In dockutil's implementation, spacers create an empty `tile-data` dictionary:
```swift
case .spacer, .smallSpacer, .flexSpacer:
    itemDictionary = [
        "GUID": newGUID as AnyObject,
        "tile-data": [String:AnyObject]() as AnyObject,
        "tile-type": opts.tileType.rawValue as AnyObject
    ]
```
Because `tile-data` is empty, `label`, `url`, and `bundleIdentifier` are all `nil`. Therefore, `--list` outputs:
```text
		persistentApps	/path/to/dock.plist	
```
for all three kinds of spacers. If an existing Dock has a `small-spacer` or `flex-spacer`, `--list` provides **zero indication** of the spacer's variant.

### 2. Tab Characters in Labels Break Column Indexing
If a dock item's label contains a tab character (e.g., set programmatically or imported):
```text
Tab	Character	https://tabsite.com	persistentOthers	/path/to/dock.plist	
```
This produces 6 tab-delimited columns instead of 5. Any parser splitting by `\t` misaligns all fields:
- Col 1: `"Tab"`
- Col 2: `"Character"` (parsed as URL!)
- Col 3: `"https://tabsite.com"` (parsed as section!)
- Col 4: `"persistentOthers"` (parsed as path!)
- Col 5: `"/path/to/dock.plist"` (parsed as bundle ID!)

### 3. Duplicate Labels & Lack of GUID
In macOS Dock plists, every item has an integer `GUID`. However, `dockutil --list` does not expose `GUID`.
- If two items share a label (e.g. duplicate app instances, two web bookmarks named "Dashboard", or multiple folders with identical names across different volumes):
  - `--list` outputs two identical lines (except possibly bundle ID or URL).
  - `dockutil --find <label>` and `dockutil --remove <label>` always stop at the first match in the section.
  - Round-tripping or targeting a specific duplicate item via CLI is impossible without modifying the plist directly.

### 4. Loss of Folder Display Configuration
In the Dock plist, folders retain:
- `showas`: `0` = auto, `1` = fan, `2` = grid, `3` = list
- `displayas`: `0` = stack, `1` = folder
- `arrangement`: `1` = name, `2` = date added, `3` = date modified, `4` = date created, `5` = kind
None of these keys are output by `--list`. If we parse `--list` to create `DockItem.folder(...)`, these properties would either be erased or forced to arbitrary defaults when written back.

### 5. `dockutil --find ""` Bug
Because of how `index(within:item:)` in `Dock.swift` is implemented:
```swift
let itemPath = URL(string: dockItem.url ?? "")?.path
if dockItem.label == item || dockItem.bundleIdentifier == item || itemPath == item || dockItem.url == item
```
Calling `dockutil --find ""` matches any URL tile whose path component is empty (e.g. `https://example.com` has `URL.path == ""`), incorrectly reporting that empty query found the web bookmark instead of failing or locating a spacer.

## 5. Plist vs. `dockutil --list` Comparison

| Field / Feature | In `com.apple.dock.plist` | In `dockutil --list` | Impact on `oh-my-dock` |
| :--- | :---: | :---: | :--- |
| **`tile-type`** | Yes (`file-tile`, `directory-tile`, `url-tile`, `spacer-tile`, `small-spacer-tile`, `flex-spacer-tile`) | **No** | Cannot determine spacer kind; cannot distinguish offline folders vs files |
| **`GUID`** | Yes (e.g. `2300454454`) | **No** | Loss of stable per-tile identifier |
| **Folder `showas`** | Yes (`0`..`3`) | **No** | Stack view style lost on read |
| **Folder `displayas`** | Yes (`0`, `1`) | **No** | Stack icon presentation lost on read |
| **Folder `arrangement`**| Yes (`1`..`5`) | **No** | Sort order lost on read |
| **App Bundle ID** | Yes (`tile-data.bundle-identifier`) | Yes (Col 5) | Both provide it, but plist is faster |
| **URL String** | Yes (`tile-data.url._CFURLString`) | Yes (Col 2) | Plist cleanly distinguishes file URL from web URL |
| **Security Bookmark** | Yes (`tile-data.book`) | **No** | Alias resolution metadata not accessible in CLI |
| **Dock Preferences** | Yes (`autohide`, `tilesize`, `magnification`, `show-recents`...) | **No** | Dock preference settings omitted by dockutil CLI |

## 6. Required Plist Keys for `DockItem` Model

For `oh-my-dock`'s `DockItem` domain model, the following plist keys are needed from each dictionary in `persistent-apps` and `persistent-others`:

### 1. Application: `DockItem.app(AppRef)`
- `tile-type` == `"file-tile"`
- Located in `persistent-apps` (or `persistent-others`)
- `tile-data.file-label`: App display name (`String`)
- `tile-data.bundle-identifier`: Primary key for bundle resolution (`String`)
- `tile-data.file-data._CFURLString`: Path URL string (e.g. `"file:///System/Applications/Calculator.app"`)
- `GUID`: Tile identifier (`Int64`)

### 2. URL Item: `DockItem.url(URL, label: String?)`
- `tile-type` == `"url-tile"`
- `tile-data.label`: Custom label (`String?`)
- `tile-data.url._CFURLString`: Target URL string (`String`)
- `GUID`: Tile identifier (`Int64`)

### 3. Folder / Stack: `DockItem.folder(path:view:display:sort:label:)`
- `tile-type` == `"directory-tile"` (or `tile-data.directory == 1`)
- `tile-data.file-data._CFURLString`: Directory URL string (`String`)
- `tile-data.file-label`: Folder display name (`String?`)
- `tile-data.showas`: View style (`Int`)
  - `0`: `.auto`, `1`: `.fan`, `2`: `.grid`, `3`: `.list`
- `tile-data.displayas`: Icon representation (`Int`)
  - `0`: `.stack`, `1`: `.folder`
- `tile-data.arrangement`: Sort order (`Int`)
  - `1`: `.name`, `2`: `.dateAdded`, `3`: `.dateModified`, `4`: `.dateCreated`, `5`: `.kind`
- `GUID`: Tile identifier (`Int64`)

### 4. Plain File: `DockItem.file(path:label:)` *(Optional addition to model)*
- `tile-type` == `"file-tile"` located in `persistent-others` (where `directory` is not set)
- `tile-data.file-data._CFURLString`: File URL string (`String`)
- `tile-data.file-label`: File name (`String`)
- `GUID`: Tile identifier (`Int64`)

### 5. Spacer: `DockItem.spacer(SpacerKind)`
- `tile-type`:
  - `"spacer-tile"` $\rightarrow$ `.normal`
  - `"small-spacer-tile"` $\rightarrow$ `.small`
  - `"flex-spacer-tile"` $\rightarrow$ `.flex`
- Can be present in either `persistent-apps` or `persistent-others`.
- `GUID`: Tile identifier (`Int64`)

## 7. Recommended Architecture for `OhMyDockCore`

```
┌──────────────────────────────────────────────────────────────┐
│                       Dock State Flow                        │
├───────────────────────────────────┬──────────────────────────┤
│           READ PATH               │        WRITE PATH        │
│    (In-Process Swift APIs)        │     (dockutil CLI)       │
├───────────────────────────────────┼──────────────────────────┤
│ 1. CFPreferencesCopyAppValue or   │ 1. Execute bundled       │
│    PropertyListSerialization from │    dockutil with:        │
│    ~/Library/Preferences/         │    --add, --remove,      │
│    com.apple.dock.plist           │    --move, etc.          │
│ 2. Parse into [DockItem]          │ 2. dockutil manages CFPrefs│
│    preserving SpacerKind, folder  │    synchronization and   │
│    view/display/sort, and GUIDs.  │    Dock reload reliably. │
└───────────────────────────────────┴──────────────────────────┘
```

### Swift Implementation Sketch for Reading:
```swift
public final class PlistDockReader {
    public static func readCurrentDock() throws -> (apps: [DockItem], others: [DockItem]) {
        // Read directly from CFPreferences to avoid disk caching desynchronization
        guard let persistentApps = CFPreferencesCopyAppValue("persistent-apps" as CFString, "com.apple.dock" as CFString) as? [[String: Any]],
              let persistentOthers = CFPreferencesCopyAppValue("persistent-others" as CFString, "com.apple.dock" as CFString) as? [[String: Any]] else {
            throw DockReadError.unableToReadPreferences
        }
        
        let apps = persistentApps.compactMap { DockItemParser.parse(tileDict: $0) }
        let others = persistentOthers.compactMap { DockItemParser.parse(tileDict: $0) }
        return (apps, others)
    }
}
```

This guarantees:
1. Zero data loss for all spacer types (`spacer`, `small-spacer`, `flex-spacer`).
2. Complete fidelity for folder stack configurations.
3. Sub-millisecond read times with zero subprocess overhead.
4. Total immunity to tab delimiters, unescaped characters, or duplicate labels.
