# Spike 0.4 — dockutil on isolated plist files

## Verdict

**Yes, with a strict caveat:** dockutil 3.1.3 can read and write an existing, non-live plist file without changing the current user's `com.apple.dock` preference domain or restarting the Dock, provided every mutating invocation includes both `--no-restart` and the explicit temporary plist *file* path.

This was verified against the bundled `App/Resources/Helpers/dockutil` (version `3.1.3`) using:

1. a byte-for-byte copy of the live plist; and
2. a synthetic XML plist containing only empty `persistent-apps` and `persistent-others` arrays.

All requested operations worked on the synthetic fixture. The Downloads operation on the copied fixture correctly failed because it already contained a `Downloads` item; it did not change the live hashes. All three spacer types are supported.

Do not pass a temporary directory as the location specification. dockutil treats a directory as a home directory and appends `Library/Preferences/com.apple.dock.plist`. Pass an absolute path to an existing plist file inside the temporary directory.

## Why this is safe for a non-live file

The 3.1.3 source at tag `3.1.3` (`640c520ce142a5f21e56fda88a95b4e4d6576042`) distinguishes the current console user's exact live plist path from every other path:

- For the exact live plist while running as the console user, it reads/writes via `CFPreferences` for `com.apple.dock`.
- For another plist path, it runs `defaults export <path> -` to read and `defaults import <path> -` to write serialized plist data. It does not call `CFPreferences` for `com.apple.dock` on that branch.
- Dock termination is guarded by `restart && isLoggedInUserDock()`. With `--no-restart` and a non-live path, neither condition permits a restart.

The source normalizes path specifications with `URL(fileURLWithPath:).absoluteURL.path`; a directory is converted to `<directory>/Library/Preferences/com.apple.dock.plist`.

## Exact working command forms

Use a file fixture, never the user's plist:

```sh
TMP="$(mktemp -d)"
PLIST="$TMP/dock.plist"
plutil -create xml1 "$PLIST"
plutil -insert persistent-apps -xml '<array/>' "$PLIST"
plutil -insert persistent-others -xml '<array/>' "$PLIST"

DOCKUTIL="$PWD/App/Resources/Helpers/dockutil"
"$DOCKUTIL" --list "$PLIST"
"$DOCKUTIL" --add /System/Applications/Calculator.app --no-restart "$PLIST"
"$DOCKUTIL" --add https://example.com --label Example --no-restart "$PLIST"
"$DOCKUTIL" --add "$HOME/Downloads" --view grid --display folder --no-restart "$PLIST"
"$DOCKUTIL" --add '' --type spacer --section apps --no-restart "$PLIST"
"$DOCKUTIL" --add '' --type small-spacer --section apps --no-restart "$PLIST"
"$DOCKUTIL" --add '' --type flex-spacer --section apps --no-restart "$PLIST"
"$DOCKUTIL" --move Calculator --position 1 --no-restart "$PLIST"
"$DOCKUTIL" --remove Calculator --no-restart "$PLIST"
"$DOCKUTIL" --list "$PLIST"
```

`--move` accepts `--no-restart` even though the short usage line does not show it. The temporary files were rewritten in Apple binary plist format, including the XML synthetic fixture; both formats are accepted as input.

## Observed plist shapes

These are trimmed `plutil -p` results from the synthetic fixture after each addition. `GUID` values are generated and vary.

### Application

```text
{
  "GUID" => 9603615037
  "tile-data" => {
    "file-data" => {
      "_CFURLString" => "/System/Applications/Calculator.app"
      "_CFURLStringType" => 0
    }
    "file-label" => "Calculator"
    "file-type" => 41
  }
  "tile-type" => "file-tile"
}
```

For this newly added app, dockutil did **not** add `bundle-identifier`; existing live-originated app tiles may have that key.

### URL

```text
{
  "GUID" => 1525462944
  "tile-data" => {
    "label" => "Example"
    "url" => {
      "_CFURLString" => "https://example.com"
      "_CFURLStringType" => 15
    }
  }
  "tile-type" => "url-tile"
}
```

The observed 3.1.3 representation is `tile-data.url._CFURLString`, not a `url-string` key.

### Folder in the others section

```text
{
  "GUID" => 8601002392
  "tile-data" => {
    "arrangement" => 3
    "directory" => 1
    "displayas" => 1
    "file-data" => {
      "_CFURLString" => "/Users/farzin/Downloads"
      "_CFURLStringType" => 0
    }
    "file-label" => "Downloads"
    "file-type" => 2
    "showas" => 2
  }
  "tile-type" => "directory-tile"
}
```

For `--view grid --display folder`, `arrangement = 3`, `showas = 2`, and `displayas = 1`.

### Spacer types

```text
{ "GUID" => 2362546764, "tile-data" => {}, "tile-type" => "spacer-tile" }
{ "GUID" => 3993094011, "tile-data" => {}, "tile-type" => "small-spacer-tile" }
{ "GUID" => 1610524733, "tile-data" => {}, "tile-type" => "flex-spacer-tile" }
```

Although the command prints `adding /Users/farzin/Projects/oh-my-dock` for an empty spacer argument, the resulting tiles are correct spacers with empty `tile-data`; no file tile is added.

## Safety observations

Every mutating command was preceded and followed by:

```sh
shasum -a 256 ~/Library/Preferences/com.apple.dock.plist
defaults export com.apple.dock - | shasum -a 256
```

The stable values before, throughout the successful mutations, and after the experiment were:

```text
live plist:   69419a9841dc95bed758ae78b3de2d285cf78f4b28667d3ffa5fd993270eb608
live domain:  c6f3274295ab899dabec1de707c511afef5c8d71551bad86d3dd671548b669f4
```

The Dock PID was `52619` before and after all operations. No Dock restart or live preference change was observed.

## Test-helper recommendation

Create a fresh `mktemp -d` directory per test, create the minimal XML fixture above, and pass its **absolute file path** as the final argument to every dockutil command. Prefer the synthetic fixture rather than copying the user's Dock: it avoids duplicate labels such as `Downloads`, avoids user-specific tile data, and makes assertions deterministic.

Keep the live file and domain hash guard around every mutation anyway. Treat any hash mismatch as an immediate test abort. Run `plutil -p "$PLIST"` after each operation for structural assertions and compare `pgrep -x Dock` before/after the test suite as a regression guard.
